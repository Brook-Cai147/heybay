fix(M2-02/04): 空字符串等于留空；重试时把字段级错误回喂给模型

第一次真实调用暴露的两个问题，链路本身是通的（模型被调到、校验执行、重试一次、优雅降级）。

问题一（校验器的 bug）：Prompt 要求「判断不了就留空」，模型老实回了 instantDuration:""
与 rewardType:""，却被判成「取值不在白名单内」。「留空」在 JSON 里有三种写法——字段缺失、
null、空字符串——校验器只认前两种。修法：nullable 字段的空串按 null 处理；同时给缺失的
nullable 字段显式补 null，让三种写法在结果里长得一样（否则端侧要同时判 undefined 和 null，
而写进云数据库时 undefined 会被丢掉、null 会存下来）。这份宽容只给 nullable 字段，
title 这类有 minLength 的空串照样报错。

问题二（白花一次钱）：decideFallback 早就产出了 retryHint，但 aiService 的重试是原样重发
同一个 Prompt——两次尝试的输入完全一样，失败方式当然也一样。现在重试会在原 Prompt 后追加
上一次的字段级错误清单。只追加一轮、不累积，避免第二次的 Prompt 带着第一次的噪音。

npm test: 133 通过 / 0 失败（新增 3 条，覆盖三种留空写法与 nullable 的边界）。
